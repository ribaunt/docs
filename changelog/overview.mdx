<Update label="August 19, 2026">

## New

**Bring-your-own rate limiting**

Both [`createChallenge`](/api/create-challenge) and [`verifySolution`](/api/verify-solution) now accept a `rateLimiter` hook. Implement the [`RateLimiter`](/api/types#ratelimiter) interface to reject abusive callers by IP, session, or user before Ribaunt spends work on token signing or verification. Rejections surface as a [`RateLimitedError`](/api/types#ratelimitederror) so you can respond with a 429.

**Lifecycle telemetry with `onEvent`**

Pass an `onEvent` callback to `createChallenge` or `verifySolution` to receive [`RibauntEvent`](/api/types#ribauntevent) values for issuance, verification success, and verification failure (with the same `reason` codes as `VerifyFailureReason`). Feed the events into your metrics or logging pipeline without wrapping Ribaunt yourself. Exceptions thrown inside the callback are swallowed, so telemetry can never break a challenge.

## Improvements

**`createChallenge` is now async**

`createChallenge()` returns `Promise<ChallengeToken[]>` so it can `await` optional hooks like `rateLimiter` before issuing tokens. Update every call site to `await createChallenge(...)`. The [quickstart](/quickstart), [Express](/server/express) and [Next.js](/server/nextjs) guides, and the [testing](/guides/testing) and [troubleshooting](/guides/troubleshooting) guides have been updated with the new signature.

</Update>

<Update label="July 10, 2026">

## New

**React and Vue integrations**

The widget now ships with first-party wrappers for [React](/integrations/react), [Next.js](/integrations/nextjs), and [Vue](/integrations/vue). Drop the component into a form, pass a callback, and receive a solved token — no manual DOM wiring required.

**Themeable widget**

Style the widget with CSS custom properties to match your design system without reaching into shadow DOM internals. See [Theming](/widget/theming) for the full list of variables.

## Improvements

**Configurable difficulty per endpoint**

Tune `difficulty`, `amount`, and `ttlSeconds` when creating a challenge to balance security and user friction on a route-by-route basis. See [`createChallenge`](/api/create-challenge).

**Pluggable replay protection**

Local in-process replay protection is on by default. For serverless or multi-instance deployments, plug in a Redis or Valkey store. See [Replay protection](/concepts/replay-protection).

**Widget events**

The widget now emits `solved`, `error`, and `expired` events so you can drive UI state directly from the challenge lifecycle. See [Widget events](/widget/events).

## Fixes

- Improved error messages when `RIBAUNT_SECRET` is missing or malformed.
- Type declarations are bundled in the package — no separate `@types` install needed.

</Update>
